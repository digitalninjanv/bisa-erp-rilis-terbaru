## Keputusan arsitektur (D1–D8)

- **D1 — Frontend dibundel, BUKAN memuat URL server.** Tauri membungkus aset statis (`frontendDist` → hasil ekspor Next). Memuat URL hosted dari webview: tanpa akses IPC secara bawaan, diperlakukan berbahaya oleh model keamanan Tauri, dan mati total saat offline. Konsekuensi jujur: **service worker POS yang ada TIDAK berjalan di dalam Tauri** — lapisan offline desktop adalah SQLite lokal, bukan SW.
- **D2 — Satu repo, satu basis kode, dua bentuk.** Ekspor statis Next (`output: 'export'`) membunuh Server Actions, route handler dinamis, middleware, ISR, dan optimasi gambar bawaan. Maka: aplikasi desktop = **POS saja** sebagai target ekspor statis terpisah, berbagi paket UI/logika dengan web (`pos-ui`, `pos-core`, `pos-platform` dengan implementasi web vs tauri yang dipilih lewat `isTauri()`). Server Actions tetap untuk web; logika layanannya yang sama dibuka kembali sebagai **endpoint hosted `/api/pos/*`** yang dipanggil desktop.
- **D3 — Jalur uang ditulis di Rust, bukan JS di atas plugin-sql.** plugin-sql resmi (sqlx) memecah BEGIN/COMMIT antar-panggilan sehingga transaksi penjualan+outbox bisa tidak atomik dan mengunci SQLite. Keputusan: **rusqlite dimiliki Rust**; satu command = satu transaksi (penjualan + baris + outbox sekaligus); WAL + `busy_timeout`.
- **D4 — Pembaruan otomatis: Linux = AppImage, Windows = NSIS.** Updater resmi Tauri hanya memperbarui AppImage di Linux (instalasi .deb/.rpm tidak bisa memperbarui diri — temuan lapangan konsisten); di Windows jangan campur MSI+NSIS. Penandatanganan updater (minisign/Ed25519) **wajib dan tidak bisa dimatikan**: kunci privat hanya di CI; **kehilangan kunci = armada tidak bisa diperbarui selamanya** (kustodi kunci = keputusan & tanggung jawab pemilik, dicatat di runbook). Rollout bertahap bukan bawaan → endpoint dinamis milik server kita yang memutuskan per perusahaan/cabang/kanal; unduh saat shift berjalan, **pasang saat tutup shift**.
- **D5 — Token perangkat di keychain OS, bukan Stronghold.** Stronghold resmi tetapi **dinyatakan usang oleh pemeliharanya (2026)** dan bukan keychain OS. Pakai crate Rust `keyring` (Windows Credential Manager / Linux Secret Service), hanya di sisi Rust. plugin-store (JSON teks biasa) hanya untuk pengaturan non-rahasia. Terbuka: kios Linux tanpa daemon secret-service butuh fallback (keputusan saat implementasi).
- **D6 — Cetak = byte ESC/POS mentah dari Rust.** Tauri tidak punya API cetak; `window.print()` di WebKitGTK dialog-bound dan raster. Jalur utama: `TcpStream` Rust ke printer jaringan port 9100 (potong kertas + tendangan laci `ESC p` dalam tugas cetak yang sama; antrean cetak ulang dari penjualan tersimpan). Plugin komunitas esc-pos masih sangat muda (v0.2.1) → hanya boleh dipakai di balik antarmuka Printer milik kita, atau byte dibuat sendiri di Rust mengikuti studi kasus POS Tauri produksi yang ditemukan riset. Scanner barcode HID = keyboard wedge, tanpa kode native.
- **D7 — Pemasangan terminal ala Accurate.** Server membuat terminal di bawah perusahaan+cabang → kode/QR sekali pakai → aplikasi memasangkan diri, menyimpan token perangkat di keychain, mengunduh snapshot pertama. Snapshot (katalog+harga cabang+metode bayar+kasir+templat struk) berversi & berkursor delta; versi snapshot dicap di setiap penjualan. Mesin sinkron outbox berjalan sebagai **task Rust (Tokio)**, bukan JS — tahan reload webview dan token tidak pernah masuk JS.
- **D8 — Lantai platform Linux = Safari 16.** Build di Ubuntu 22.04 (WebKitGTK 4.1); WebKitGTK 2.36 ≈ Safari 16 adalah lantai CSS/JS POS di platform utama. AppImage membawa WebKit sendiri (risiko isu Mesa/Wayland di sebagian mesin; .deb memakai WebKit sistem).

## Permukaan API hosted yang dibutuhkan (baru, berbagi logika layanan dgn Server Actions)
`POST /api/pos/pair` (tukar kode pasangan → token perangkat) · `GET /api/pos/snapshot?cursor=` (delta katalog/harga/pengaturan per cabang) · `POST /api/pos/sync` (kontrak idempoten yang SUDAH ada dipakai ulang: terima/flag review/tolak beralasan) · `GET /api/pos/update/:target/:arch/:version` (endpoint dinamis updater, gerbang versi minimum shell) · status terminal (revoke diperiksa saat sync/login/update).
